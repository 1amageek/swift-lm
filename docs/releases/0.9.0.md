# swift-lm 0.9.0

`0.9.0` is an LFM2.5 8B-A1B direct-Metal performance and release-readiness
minor release. It does not change the public API. The release scope is the
non-quantized HuggingFace-bundle path for `LiquidAI/LFM2.5-8B-A1B`, the
lightweight exact release benchmark executable, and the compiler/runtime
contract hardening needed to ship the 90 tok/s decode route safely.

## What 0.9.0 Changes

### LFM2.5 ShortConv decode fusion

The default LFM2.5 A1B decode route now fuses each ShortConv layer's
`in_proj` projection with the convolution-state update in
`shortconv_inproj_update_bf16`. This removes the separate ShortConv
projection/update pair from the hot decode path and drops the default
exact-trace plan from `202` to `184` decode steps.

The fusion is admitted only when the compiler can prove the local contract:

- BF16 decode and BF16 weights
- `in_proj` shape `2048 -> 6144`
- ShortConv channel dimension `2048`
- same composite and same layer
- both `in_proj` and convolution weights resolved from non-fallback STAF
  descriptors
- BF16 row-major STAF scheme and row-major layout for both weight reads

The fused kernel is covered by a bit-exact generated-kernel equivalence test
against the unfused `in_proj + conv_state_update` route. Admission coverage
also rejects cross-composite and non-row-major BF16 layouts.

### Release benchmark tooling

The `lfm25-a1b-benchmark` release executable validates the strict-capital
64-token HuggingFace trace before reporting timing. It now reports:

- warmup and measured wall-token samples
- decode step count
- barrier count and visibility histogram
- host logit read count
- kernel, barrier-kernel, pair, and triple histograms

This keeps release performance evidence tied to exact output correctness and
makes dispatch-count regressions visible without running the full xctest
product.

### 90 tok/s decode route

The default non-quantized BF16 route now combines the accepted dispatch and
binding optimizations from the M5 workstream:

- ShortConv in-projection/state fusion
- fused residual/RMS/router dispatch for Sparse MoE layers
- staged packed4 BF16 gate/up projections
- packed4 BF16 down projections
- blocked vocab output-head partial argmax for the greedy release gate
- encoded argument-buffer variants for the hot fused router, MoE, vocab
  partial-argmax, and argmax-reduce kernels

The exact-trace release benchmark now clears the M5 target with `90.4` median
wall tok/s over ten measured iterations. The full decision record is
[`docs/development/lfm25-a1b-m5-progress.md`](../development/lfm25-a1b-m5-progress.md).

### Diagnostic routes remain out of the default path

Rejected diagnostic routes such as unsafe barrier elision, monolithic Sparse
MoE, packed8/row-sharing MoE variants, private-logits shortcuts, and
quantized-Q8 evidence remain outside the default BF16 production route.

## Performance Evidence

The focused release evidence records:

- final default BF16 route: `162` decode steps, `161` barriers,
  `host_logit_reads=0`
- clean exact release rerun: `90.4` median wall tok/s
- best measured sample: `90.7` wall tok/s
- minimum measured sample: `90.1` wall tok/s
- M5 target: `90.0` wall tok/s

`0.9.0` therefore claims the LFM2.5 8B-A1B 90 tok/s M5 goal for the scoped
local exact-trace release benchmark.

## Correctness

Validated before release with focused checks:

- `perl -e 'alarm shift; exec @ARGV' 120 swift build -c release --product lfm25-a1b-benchmark`
- `perl -e 'alarm shift; exec @ARGV' 120 xcodebuild build-for-testing -scheme swift-lm-Package -destination 'platform=macOS'`
- `perl -e 'alarm shift; exec @ARGV' 120 xcodebuild test-without-building -scheme swift-lm-Package -destination 'platform=macOS' -only-testing:MetalCompilerTests/MetalSourceGeneratorTests`
- `perl -e 'alarm shift; exec @ARGV' 120 xcodebuild test-without-building -scheme swift-lm-Package -destination 'platform=macOS' '-only-testing:SwiftLMTests/LFM25A1BRealBundleTests/productionSparseMoERouteUsesA1BOptimizedKernels()'`
- `perl -e 'alarm shift; exec @ARGV' 120 xcodebuild test-without-building -scheme swift-lm-Package -destination 'platform=macOS' '-only-testing:SwiftLMTests/LFM25A1BRealBundleTests/realPackedSparseMoEKernelMatchesCPUReference()'`
- `perl -e 'alarm shift; exec @ARGV' 120 xcodebuild test-without-building -scheme swift-lm-Package -destination 'platform=macOS' '-only-testing:SwiftLMTests/LFM25A1BRealBundleTests/defaultSparseMoERouteReportsDecodeTimingBreakdown()'`
- `perl -e 'alarm shift; exec @ARGV' 120 xcodebuild test-without-building -scheme swift-lm-Package -destination 'platform=macOS' '-only-testing:MetalCompilerTests/LFM25A1BDecodeProfileTests/a1bDecodeStepProfileIdentifiesHotKernelFamilies()'`
- `perl -e 'alarm shift; exec @ARGV' 120 .build/release/lfm25-a1b-benchmark --tokens 64 --warmup 1 --iterations 10 --require-m5`

Full target-wide `SwiftLMTests` and `MetalCompilerTests` are still too large
to use as a single release gate on the local machine. Release validation should
continue to use focused `build-for-testing` plus `test-without-building`
invocations for heavy real-bundle suites.

## Notes

- No migration is required. There are no public API changes in this release.
- The LFM2.5 A1B 90 tok/s performance claim is scoped to the exact-trace
  focused local bundle gate above.
- The legacy monolithic Sparse MoE route remains diagnostic-only and must not
  be used as a correctness oracle.
- Do not describe this release as whole-package production readiness without
  the broader production-readiness matrix.
