# swift-lm 0.11.0-alpha.1

This alpha release moves the primary architecture to Apple Core AI while
keeping the 0.10 direct Metal runtime available for compatibility.

## Architecture

```text
Swift model declaration
        |
        v
LMIR + parameter bindings
        |
        v
Core AI executable contract
        |
        v
generic LMIR-to-coreai-torch lowerer
        |
        v
      .aimodel
        |
        v
Core AI runtime on macOS/iOS 27+
```

## Included

- `CoreAIExport` for deterministic, versioned graph documents.
- `SwiftLMCoreAI` for asset validation and contract-checked stateless/stateful
  low-level inference through `CoreAIExecutableSession`.
- `SwiftLMFoundationModels` for Apple's `CoreAILanguageModels` LLM and VLM
  bundle APIs, including strict three-asset VLM loading and actor-isolated image
  generation.
- `swiftlm-ir` for local Hugging Face `config.json` to graph export.
- `python/` tooling for strict document validation and generic Swift LMIR
  lowering through `coreai-torch`.
- Transformer, dense LFM2, SwiGLU MoE, and Qwen3.5 text-hybrid declarative
  graph coverage in the current lowerer, with tokenizer files and the source
  contract included in bundles.
- Softmax Top-K and LFM2 sigmoid Top-K routing lower through Apple's
  `SwitchGLU`, including selection-only expert bias, optional normalization,
  and routed scaling.
- Stateful LFM2 export exposing persistent `keyCache`, `valueCache`, and
  `convCache` derived from Swift operation bindings.
- Qwen3.5 GatedDeltaNet lowering through Apple's `GatedDeltaUpdate`, including
  causal convolution state, float32 recurrent state, per-head gated RMSNorm,
  and packed sigmoid attention output gates.
- Hugging Face tokenizer assets are copied into generated bundles without
  requiring Transformers to instantiate a model-specific tokenizer class.
- Explicit capability errors for unsupported expert MLPs, state-space
  variants, vision lowering outside Apple's official VLM exporter, and
  advanced attention semantics that are not yet implemented. No model-family
  fallback graph is used.

## Compatibility

- Deployment target is macOS 27.0+ and iOS 27.0+.
- Xcode 27 and the matching Core AI SDK are required.
- `MetalCompiler` and `SwiftLM` remain the 0.10 direct Metal compatibility
  products.
- The Core AI state wrapper supports arbitrary NDArray state counts with
  persistent Metal buffers and rejects unsupported image states with typed
  errors.

## Verification

The following checks passed for this release candidate:

- Swift release build for `swiftlm-ir`.
- Full Swift debug package build.
- Full package builds for generic iOS and Mac Catalyst destinations.
- `CoreAIExportTests` and `SwiftLMCoreAITests` through `xcodebuild`.
- `SwiftLMFoundationModelsTests`, including a three-asset VLM generated with
  `coreai_torch` and executed through image encoding and stateful decoding.
- Python document, routing, and stateful export tests.
- Core AI asset inspection with `xcrun coreai-build inspect`.
- Real `yujiepan/lfm2-tiny-random` stateless logits matched Hugging Face with
  `0.001220703125` maximum absolute error and exact Top-5 token IDs.
- The same Swift graph's stateful and stateless paths matched exactly across
  sequential tokens in Python.
- A generated stateless LFM2 `.aimodel` ran through
  `CoreAIModelBundle.makeStatelessSession()` in Swift and returned the
  contract-declared logits shape.
- A generated stateful LFM2 `.aimodel` passed asset inspection and the Swift
  runtime state-persistence/reset regression test.
- The local `yujiepan/lfm2-moe-tiny-random` bundle lowered from Swift LMIR with
  canonical per-expert weights; stateless and stateful logits matched exactly
  across four decode steps, and both Core AI 27 assets passed inspection.
- The local `yujiepan/qwen3.5-tiny-random` text graph matched the Hugging Face
  float32 reference with maximum logits error `1.52e-6`. Stateless and stateful
  Core AI 27 assets passed inspection, and Swift runtime execution matched the
  reference final-token argmax while preserving token-by-token state.

Larger production model bundles still require model-specific validation before
publishing an application asset. Core AI beta compiler warnings may appear on
Apple Silicon during these smoke tests; the process must still complete and
the output must be compared with the reference model.
