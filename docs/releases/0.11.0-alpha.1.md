# swift-lm 0.11.0-alpha.1

This alpha release moves the primary architecture to Apple Core AI while
keeping the 0.10 direct Metal runtime available for compatibility.

## Architecture

```text
Swift model declaration
        |
        v
LMIR + parameter bindings
        |
        v
Core AI export document
        |
        +--> Apple's standard Transformer exporter
        |
        +--> low-level Core AI Torch program exporter
        |
        v
      .aimodel
        |
        v
Core AI runtime on macOS/iOS 27+
```

## Included

- `CoreAIExport` for deterministic, versioned graph documents.
- `SwiftLMCoreAI` for asset validation, specialization, state allocation, and
  low-level inference.
- `SwiftLMFoundationModels` for Apple's `CoreAILanguageModels` bundle API.
- `swiftlm-ir` for local Hugging Face `config.json` to graph export.
- `python/` tooling for document validation, Apple's standard exporter, and
  custom stateful `coreai-torch` programs.
- Transformer and LFM2 declarative graph coverage in the export contract.
- A dynamic stateless LFM2/LFM2 MoE exporter backed by Hugging Face
  `AutoModelForCausalLM`, with tokenizer files included in the bundle.
- Explicit low-level routing for LFM2 and LFM2 MoE rather than an unsupported
  high-level fallback.

## Compatibility

- Deployment target is macOS 27.0+ and iOS 27.0+.
- Xcode 27 and the matching Core AI SDK are required.
- `MetalCompiler` and `SwiftLM` remain the 0.10 direct Metal compatibility
  products.
- The Core AI state wrapper currently supports up to four NDArray states and
  rejects unsupported image states with typed errors.

## Verification

The following checks passed for this release candidate:

- Swift release build for `swiftlm-ir`.
- Full Swift debug package build.
- `CoreAIExportTests` and `SwiftLMCoreAITests` through `xcodebuild`.
- Python document, routing, and stateful export tests.
- Core AI asset inspection with `xcrun coreai-build inspect`.
- Stateful Core AI runtime smoke: repeated input produced `1.0`, then `2.0`.
- Real `yujiepan/qwen3-tiny-random` standard Transformer export and runtime
  smoke with Hugging Face Top-5 token parity.
- Real `yujiepan/lfm2-tiny-random` and `yujiepan/lfm2-moe-tiny-random` export
  and runtime smoke with dynamic sequence output.
- LFM2 MoE dense-routing conversion matched the CPU Hugging Face reference
  within `3e-8` maximum absolute logit error.

Larger production model bundles still require model-specific validation before
publishing an application asset. Core AI beta compiler warnings may appear on
Apple Silicon during these smoke tests; the process must still complete and
the output must be compared with the reference model.
