# swift-lm 0.10.0

`0.10.0` is a minor release for the LFM2.5 A1B direct-Metal path and release
validation workflow. It keeps the public API stable while hardening sparse MoE
decode routing, preserving CPU-readable logits for the partial-argmax output
head, and making the generation benchmark release gate repeatable under the
repository's 120-second focused-test policy.

## What 0.10.0 Changes

### Sparse MoE decode routing hardening

Sparse MoE decode routing now has focused contract coverage for the optimized
decode route. The regression coverage verifies that routing decisions and
scratch-buffer access stay aligned with graph semantics instead of relying on
dispatch entry order.

This protects the LFM2.5 A1B route where sibling projections and expert paths
must share the intended source buffers while still allowing the compiler to
emit optimized staged packed kernels.

### Partial-argmax logits preservation

The optimized vocab output-head partial-argmax kernels now also write the
CPU-readable logits buffer. This keeps the fast greedy decode path compatible
with runtime surfaces that inspect logits, including debug prefill top-logit
inspection and host-side sampling paths.

If partial-argmax pipelines are unavailable, the compiler now falls back to the
normal GEMV output-head path instead of failing the whole dispatch plan. The
fallback is explicit at the compiler decision boundary and does not introduce
silent runtime recovery.

### Repeatable generation release gate

`scripts/benchmarks/run-generation-pipeline.sh` now scopes its
`build-for-testing` invocation to the selected benchmark suites or cases and
splits the default generation benchmark matrix into focused entries. This keeps
the release benchmark command usable within the 120-second outer timeout while
still covering throughput, scaling, long-context scaling, streaming chunk size,
and prompt-state reuse.

pipeline command completed from build through benchmark execution after the

The full benchmark suite is still too long to use as one local release process,
so release validation should continue to run its heavy cases individually.

## Notes

- No migration is required. There are no public API changes in this release.
- The release does not expand the public support boundary beyond the model
  families and runtime paths already documented for `0.9.0`.
- Performance claims remain tied to correctness-first focused gates; benchmark
  output is not treated as release evidence when output correctness fails.
