# swift-lm 0.8.7

`0.8.7` is an LFM2.5 8B-A1B performance and focused-readiness patch
release. It does not change the public API. The release scope is the direct
Metal HuggingFace-bundle path for `LiquidAI/LFM2.5-8B-A1B`, plus the focused
test-contract stabilization needed to keep release validation reproducible.

## What 0.8.7 Changes

### LFM2.5 8B-A1B decode routing

The LFM2.5 A1B Sparse MoE route now uses the split production path with the
parallel expert router enabled by default. The default route keeps the
HuggingFace 64-token strict-capital trace exact while reducing decode dispatch
steps from the previous score/select router path.

The release evidence records the current focused performance gate:

- HF 64-token strict-capital trace matches exactly.
- Default decode timing reports `85.2` wall tok/s and `89.3` GPU tok/s on the
  local A1B bundle.
- The default route uses `sparse_moe_bf16_router_parallel`,
  `sparse_moe_bf16_gate_up_packed4`, and `sparse_moe_bf16_down_packed4`.
- Disabling the parallel router remains available for A/B diagnostics through
  `SWIFTLM_SPARSE_MOE_DISABLE_ROUTER_PARALLEL=1`.

### Focused validation stability

Several focused tests were updated to match the current compiler contracts:

- Fused sequence-kernel tests now bind explicit runtime row strides and compare
  against the same sequence storage precision used by generated Metal kernels.
- Kernel scaffold tests now assert the runtime row-stride sequence contract.
- The Sequence GEMV microbenchmark admission CSV assertion now matches the
  current schema.
- LFM strict prompt reference tests explicitly skip only when the optional local
  strict reference snapshot is absent.
- EmbeddingGemma prefill step isolation reuses the loaded container within the
  diagnostic suite and has a wider per-test time limit to avoid false red from
  first-load cost.

## Correctness

Validated before release with focused, one-process-at-a-time checks:

- `swift build`
- `xcodebuild build-for-testing -scheme swift-lm-Package -destination 'platform=macOS'`
- `ModelsTests`
- `MetalCompilerTests/MetalSourceGeneratorTests`
- `MetalCompilerTests/FusionVerificationTests`
- `MetalCompilerTests/SequenceGEMVMicrobenchmarkTests`
- `MetalCompilerTests/LFMStrictPromptReferenceTests`
- `SwiftLMTests/KernelScaffoldTests`
- `SwiftLMTests/EmbeddingPrefillStepIsolationTests`
- LFM2.5 A1B focused real-bundle gates recorded in
  `docs/releases/lfm25-a1b-production-readiness-2026-05-30.md`

Full target-wide `SwiftLMTests` and `MetalCompilerTests` are still too large to
use as a single release gate on the local machine because real-bundle and
benchmark suites can exceed the 120-second outer timeout or exhaust GPU memory
when run together. Release validation should continue to use focused
`build-for-testing` plus `test-without-building` invocations.

## Notes

- No migration is required. There are no public API changes in this release.
- The LFM2.5 A1B performance claim is scoped to the focused local bundle gates
  above.
- Do not treat the legacy monolithic Sparse MoE route as a correctness oracle;
  it remains diagnostic-only.
- Do not claim whole-package production readiness from this note alone. Use the
  production-readiness matrix for broader release claims.
